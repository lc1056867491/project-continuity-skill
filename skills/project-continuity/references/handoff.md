# 交接会话（handoff）

仅在调用 `$project-continuity 交接会话` 时读取本文件；必须先按 [sync.md](sync.md) 完成增量同步核对。

## 目标

在结束当前长会话前保存精简、结构化、可恢复的状态，使后续新会话能够继续未完成任务。

## 流程

1. 确认同步结果，并检查状态文档是否反映真实进度。优先使用 `PROJECT_STATE.md`；项目已有等效状态文件时继续复用。
2. 整理本会话已完成工作与重要决定、正在进行的任务、未完成事项、下一会话必须知道的约束、关键路径、问题和阻碍。
3. 明确尚待用户确认的事项，以及下一会话最优先且具体可执行的一项任务。
4. 在状态文件中新增或更新一个简短交接区块。标记交接时间；使用当前客户端的本地日期时间并注明时区，无法确定时区时明确写“时区待确认”，不要猜测。
5. 优先更新现有交接区块或当前状态，不为已同步内容生成大段副本。不要复制整段聊天，也不要把推测写成已记录事实。
6. 保存后重新读取交接区块，确认字段完整、引用路径存在或已明确标记缺失。

## 交接区块最少信息

- 当前项目名称和根目录；
- 当前项目阶段；
- 当前任务；
- 已完成事项；
- 未完成事项；
- 已确认的重要约束；
- 尚待用户确认的事项；
- 关键资料位置；
- 下一步具体任务。

如果历史重要信息缺失，列出缺失项；无法访问旧会话时直说。保存失败时必须报告失败，不能声称交接成功。

## 完成报告

输出简短中文交接报告，包含更新文件、当前任务、未完成事项、阻碍和下一步。提醒用户先确认文档已保存成功，再由用户自行建立新会话；本模式不能自动开启新会话或删除旧会话。报告后停止，不追加无关的长时间分析。
