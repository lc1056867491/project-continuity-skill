# 同步进度（sync）

调用 `$project-continuity 同步进度` 时读取本文件。交接模式也先执行本流程。

## 目标

把当前会话新增且有长期价值的信息增量写入当前项目档案；没有新信息时保持文件不变。

## 流程

1. 确认当前项目、项目根目录以及分别承担目标、需求、资料索引和状态职责的文档。
2. 从当前会话和实际成果中整理候选增量：已完成工作、用户确认的结论、尚未确认的 AI 建议、新问题、需求变更、重要来源和下一步。
3. 与现有文档逐项比较，只保留确实新增、状态改变或需要纠正的内容。相同事实、同一待办和已记录来源不重复追加。
4. 按职责更新最少数量的相关文件：
   - 需求和变更写入需求文档；
   - 重要来源、路径及适用限制写入资料索引；
   - 实际进度、阻碍、问题和下一步写入状态文档；
   - 长期有效且跨任务的项目工作约束才写入项目级 `AGENTS.md`。
5. 需求发生变化时，记录新结论、确认状态和来源，并明确旧结论已被取代或仍然有效；不能让新旧表述无说明地互相矛盾。
6. 保存后重新比较或读取相关区块，确认只产生预期增量。再次执行同一同步时不应出现重复记录或无意义改动。

## 状态和证据规则

- 用户明确同意或项目证据已经证明的内容可标记 `已确认` 或 `已完成`。
- 尚未得到用户确认的方案标记 `AI 建议` 或 `待确认`。
- 尚未实际完成的工作标记 `计划中`、`进行中` 或 `未完成`，不能写成已实现。
- 重要资料记录可追溯路径或来源，并保留其原始适用范围；不把局部报告推广为整个产品或项目的结论。
- 只更新管理文档，不修改无关代码、业务内容或配置。

如果没有新的有效信息需要保存，不修改文件，并明确报告“无需更新”。

## 完成报告

用中文报告：本次实际完成内容、更新文件、已确认事项、待确认事项和建议的下一步。若部分保存失败，逐项说明失败文件和未保存内容。
