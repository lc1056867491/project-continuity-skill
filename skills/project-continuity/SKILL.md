# 项目连续性管理

仅在用户显式调用 `$project-continuity` 后执行本 Skill。它管理通用流程；每个项目的需求、资料、状态和决定仍保存在该项目自己的工作目录中。

## 识别操作模式

读取 `$project-continuity` 后的中文操作名称，并按下表路由。操作名称后的附加说明只限定关注范围，不改变模式。

| 中文调用 | 内部模式 | 处理方式 |
| --- | --- | --- |
| `$project-continuity 初始化项目` | `init` | 读取 [references/init.md](references/init.md) |
| `$project-continuity 同步进度` | `sync` | 读取 [references/sync.md](references/sync.md) |
| `$project-continuity 交接会话` | `handoff` | 先读取 [references/sync.md](references/sync.md)，再读取 [references/handoff.md](references/handoff.md) |
| `$project-continuity 恢复项目` | `resume` | 读取 [references/resume.md](references/resume.md) |

例如，`$project-continuity 同步进度 重点整理本次产品库需求` 仍是 `sync`，只是优先整理指定内容。

如果用户只调用 `$project-continuity`，用中文说明以上四种调用，不创建、修改或删除任何文件。如果模式不明确、目录可能指错项目或操作可能误改重要内容，先询问最关键的一个问题。

## 共同执行规则

1. 先识别当前实际工作目录和项目根目录；路径不明确时先核实。只操作本次项目，不跨项目读取或修改资料，除非用户明确要求。
2. 先检查已有目录和管理文档，建立“现有文件 → 管理职责”的映射。优先复用有效文档，不因缺少推荐文件名而覆盖现有工作方式或创建功能重复的文件。
3. 明确区分 `已确认`、`待确认`、`AI 建议`、`已完成`、`计划中`。未知信息写为“待确认”；不能把建议写成用户需求，也不能把计划写成成果。
4. 重要事实保留可追溯的文件路径或来源及适用限制。未经核实，不扩大检测报告、参考资料或证据的适用范围。
5. 不删除原有业务文件，不覆盖有效需求或资料，不擅自修改业务代码、产品内容、API 地址、密钥、环境变量、模型配置或上下文压缩配置。
6. 不读取、复制、展示或记录凭证。发现疑似凭证时跳过内容，只报告需要用户自行处理的文件位置；不得把凭证写入项目档案。
7. 对可能造成重要内容丢失或冲突的操作，先说明差异、目标路径和预期改动，取得确认后再执行。
8. 只把工具实际成功保存的内容报告为成功。无法访问的文件或历史对话必须明确说明，不猜测补全。
9. 所有模式名称、操作说明、进度报告和主要提示使用简体中文。

## 上下文与成本控制

- 优先读取项目状态摘要，再按当前任务读取目标、需求或资料索引；不一次性重读大型报告、媒体文件、整个代码库或无关文档。
- 项目文档保存完整事实；交接摘要只保存当前状态、恢复所需约束和必要引用。
- 同步与交接采用增量更新，不反复生成完整历史，也不复制整段聊天。
- 用户主动要求交接时，完成保存与报告后停止，不擅自追加长时间分析。
- 不自行监控上下文 Token 数量，不承诺低于特定 Token 阈值，也不修改 Codex 自动压缩设置。
